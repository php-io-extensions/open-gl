# OpenGL binding rules

Audit truth is the vendored Khronos headers in `scripts/khronos/` (and, for
CGL, the live `OpenGL.framework` headers on Darwin) — see the README there
for provenance. Layering: **ext-opengl = OpenGL + unavoidable glue;
jovian/ogx = PHP projection; venusian = composition; surface = abstraction.**

## Inherited wholesale

ext-gtk's and ext-metal's generic rules apply here without change:

- **One PHP static method = one native call.** No composites at all in this
  extension: there is no constructor/sink exception to make, because OpenGL
  has no objects to register.
- The `/*@zep …*/` annotations in `src/*.h` are the single source of truth
  for the PHP surface; everything under `opengl/` (zep) and `optimizers/` is
  generated by `scripts/gen-zep.php` and never hand-edited. No inline C in a
  `.zep` file, ever. No FFI.
- **Nothing silently omitted.** Anything unbindable stays as a commented
  `@reserved` line, and `bound + reserved` must equal the header's prototype
  count for the class. `@audit partial <class> <reason>` sanctions a
  shortfall (never an excess) while a class is deliberately incomplete —
  metal's semantics exactly.
- No error side channel. A refused call raises `E_WARNING` and returns
  `0`/void. There is no process-global "last error" (that was dep-gtk's ZTS
  bug and it is not repeated).
- Constants live in **jovian/ogx** as PHP enums, never in the ext.
- Zephir reserved words and all-caps identifiers follow the house
  underscore/mixed-case rules in `gen-zep.php`. **No method name hits either
  rule** — every GL, EGL and CGL function name passes through verbatim — but
  **three parameter names do**, and callers using named arguments need to
  know which:

  | function | header parameter | PHP parameter |
  |---|---|---|
  | `GL20::glShaderSource` | `string` | `string_` |
  | `GL30::glBindVertexArray` | `array` | `array_` |
  | `GL30::glIsVertexArray` | `array` | `array_` |

  Positional calls are unaffected. The escaping is `gen-zep.php`'s, applied
  to the annotation the generator wrote from the header, so it stays in
  lockstep with the header rather than being a list anyone maintains.

**What is different here:** `src/gl-*.{h,c}`, `src/egl.{h,c}`,
`src/cgl.{h,c}` and their type headers are *themselves* generated, by
`scripts/gen-gl-src.php`, out of the vendored headers. A hand-written
binding body does not exist in this repo. gtk hand-writes its C and
generates only the zep layer; here the mechanical translation goes one level
deeper, because 572 bodies of identical shape are not something a human
should type.

## D1 — surface and grouping

One static class per header version block, class path root `OpenGL\`, house
FQCN shape (namespace-per-class):

| `GL_VERSION_1_1` | `OpenGL\GL\GL11\GL11` | `src/gl-11.{h,c}` | 14 |
| `GL_VERSION_1_2` | `OpenGL\GL\GL12\GL12` | `src/gl-12.{h,c}` | 4 |

| `OpenGL.h` + `CGLCurrent.h` + `CGLDevice.h` + `CGLIOSurface.h` | `OpenGL\CGL\CGL` | `src/cgl.{h,c}` | 52 (50 bound, 2 reserved) |
| — (glue) | `OpenGL\Bridge\Bridge` | `src/phpgl-bridge.{h,c}` | 8 |

**479 GL + 44 EGL + 50 CGL + 8 Bridge = 581 static methods, 17 classes,
2 reserved** (CGL's header count is 52; the two reserved are below).

**Method name = the function name verbatim.** `GL10::glClear`,
`GL15::glGenBuffers`, `EGL::eglMakeCurrent`, `CGL::CGLCreateContext`. A
method is never renamed, never camel-cased, never de-prefixed — the whole
point is that a C tutorial reads as PHP with `GL30::` in front of it.

**A function belongs to the block it first appeared in, and only that one.**
`glClear` lives on `GL10` and nowhere else; a 4.1 context calls
`GL10::glClear`, not `GL41::glClear`. That is why the classes are named for
the version a call *arrived* in, not the version you are running.

**No class exists for a deferred or out-of-scope block.**
`GL_VERSION_4_2` .. `4_6` (178 prototypes) are a later wave and the audit
reports them as deferred; extension blocks are out of scope permanently.

## D2 — the pointer line (the unopinionated rule)

This is the decision that keeps the extension free of opinions. Every
pointer that is not a string crosses as **raw pointer bits in a PHP int**,
`0 = NULL`. PHP owns the bytes, `pack()`/`unpack()` owns the typing, and the
extension makes no judgement about what any pointer points at or how many
elements are behind it.

| C type | PHP | how it crosses |
|---|---|---|
| `GLenum` `GLint` `GLuint` `GLsizei` `GLbitfield` `GLintptr` `GLsizeiptr` `GLint64` `GLuint64` `GLshort` `GLushort` `GLbyte` `GLubyte` | `int` | by value |
| `GLsync` | `int` | pointer bits (it is a `struct __GLsync *`) |
| `GLfloat` `GLdouble` `GLclampf` `GLclampd` | `double` | by value |
| `GLboolean` | `bool` | by value |
| `const GLchar *` (in) | `string` | borrowed NUL-terminated bytes |
| `const GLchar *const *` (in) | `array` of strings | `phpgl_arg_strv` builds a `char **` for the call and frees it after |
| `const GLubyte *` (return) | `var` | copied to a PHP string; `null` when NULL |
| `EGLDisplay` `EGLConfig` `EGLContext` `EGLSurface` `EGLSync` `EGLImage` `EGLClientBuffer` `EGLNative*Type` | `int` | pointer bits |
| `CGLContextObj` `CGLPixelFormatObj` `CGLPBufferObj` `CGLRendererInfoObj` | `int` | pointer bits |
| `EGLint` `EGLenum` `EGLTime`, every CGL enum | `int` | by value |
| `CGLError` (return) | `int` | by value |
| `const char *` (return; `eglQueryString`, `CGLErrorString`) | `var` | copied; `null` when NULL |
| **every other pointer** — `void *`, `const void *`, `GLint *`, `GLuint *`, `GLfloat *`, `GLchar *` (out), `void **`, `const void *const *`, … | `int` | **raw pointer bits, 0 = NULL** |

Consequences, all deliberate:

- **No `count` parameter is ever invented and none is ever dropped.**
  `glGenBuffers(int n, int buffers)` takes the same two arguments C does.
- **Out-parameters are buffers, not return values.** `glGetIntegerv` writes
  into a `Bridge::alloc`'d block; PHP `unpack`s it. Nothing is guessed about
  how many values a `pname` produces — that is exactly the judgement a 1:1
  layer must not make.
- **`GLchar *` (non-const) is a pointer, not a string.** `glGetShaderInfoLog`
  writes into a Bridge buffer like any other out-param; only `const GLchar *`
  *in* is a PHP string.
- **A prototype this table cannot express becomes a visible `@reserved`
  line**, counted by the audit toward its class's header total — never a
  silent absence, and never a hard stop. Exactly two kinds qualify, and the
  emitted line says which:

  | kind | why | today |
  |---|---|---|
  | callback | a function-pointer parameter; PHP cannot be a C function pointer and there is no callback glue | none in 1.0 .. 4.1; `glDebugMessageCallback(GLDEBUGPROC, …)` at 4.3 is the first, proved by `scripts/tests/reserved-guard.php` against a scratch build |
  | foreign | a type owned by a framework this binding does not include | `CGLGetDeviceFromGLRenderer` (`cl_device_id`, OpenCL) and `CGLTexImageIOSurface2D` (`IOSurfaceRef`, IOSurface.framework) |

  `CGLGetShareGroup` is deliberately **not** in that second row.
  `CGLShareGroupObj` is declared in `CGLDevice.h` itself and is an ordinary
  CGL opaque handle, so the pointer rule covers it exactly as it covers
  `CGLContextObj`; reserving it would have been the per-function judgement
  this rule exists to prevent.

- **Anything else the table does not cover still stops the generator**, by
  name. A type that is neither a callback nor foreign must not be quietly
  reserved away — that would let a new scalar spelling shrink the surface
  without anyone noticing. `reserved-guard.php` proves this half too, by
  making a known scalar unmappable and asserting the generator dies.

### The one guard in a generated body

The pointer line means a caller can hand GL nonsense and get a segfault;
that is the documented cost (see
[traps/pointer-bits-only.md](/traps/pointer-bits-only.md)). There is exactly
one place the generator refuses to be that literal: an array-of-strings
parameter, where the caller's `count` and the array's length can disagree
and GL would read past the end of an array *this extension allocated*.

Every such parameter in these headers is immediately preceded by a
`GLsizei count`, so the generated body compares the two and refuses the call
with a warning when `count` is larger. The rule is derived from the header's
parameter order, not from knowledge of any particular function, and a header
that breaks the shape **stops the generator** rather than getting a
special case. Four functions are affected: `glShaderSource`,
`glTransformFeedbackVaryings`, `glGetUniformIndices`,
`glCreateShaderProgramv`.

## D3 — context creation, platform-conditional, still 1:1

The extension binds both OS-native context APIs, under the same rules as
everything else, and **chooses neither**. Choosing is the caller's job:
`examples/proof_headless.php` branches on `PHP_OS_FAMILY` in exactly one
function and that is the only platform decision anywhere in this repo's PHP.

- `OpenGL\EGL\EGL` — EGL 1.0 .. 1.5 core, bound from the vendored
  `scripts/khronos/egl.h`. The headless Linux path is
  `eglGetPlatformDisplay(EGL_PLATFORM_SURFACELESS_MESA, …)` →
  `eglInitialize` → `eglBindAPI` → `eglChooseConfig` → `eglCreateContext` →
  `eglMakeCurrent(…, EGL_NO_SURFACE, EGL_NO_SURFACE, ctx)`. Attribute lists
  are Bridge buffers of packed 32-bit ints; out-parameters are Bridge
  buffers read back with `unpack`.
- `OpenGL\CGL\CGL` — bound from the live macOS SDK headers. The headless
  Darwin path is `CGLChoosePixelFormat` → `CGLCreateContext` →
  `CGLSetCurrentContext`, with `kCGLPFAOpenGLProfile` /
  `kCGLOGLPVersion_GL4_Core` in the attribute buffer.
- **Both classes exist on both platforms**, because every entry point is
  resolved at runtime. `CGL::CGLCreateContext` on Linux simply never
  resolves and warns; there is no `#ifdef` anywhere in the generated C.
- Windowed paths — `GtkGLArea`, `NSOpenGLView`, `CAMetalLayer` — are other
  repos' waves. This one never touches a window
  ([traps/no-window-in-ext.md](/traps/no-window-in-ext.md)).

## Mechanics

- C symbol: `phpgl_<classlower>_<functionlower>(zval *…)` —
  `phpgl_gl15_glgenbuffers`, `phpgl_egl_eglmakecurrent`,
  `phpgl_cgl_cglcreatecontext`. GL function names are globally unique, so the
  symbol is too.
- Every generated body has exactly this shape, and the parity guard enforces
  it structurally:

  ```c
  void phpgl_gl10_glclear(zval *mask)
  {
      static phpgl_slot slot = PHPGL_SLOT_INIT;
      PFNGLCLEARPROC fn = (PFNGLCLEARPROC) phpgl_entry("glClear", &slot, 1, 0);

      if (!fn) {
          return;
      }

      fn((GLbitfield) phpgl_arg_long(mask));
  }
  ```

  One `phpgl_entry()`, one `fn()`, no GL/EGL/CGL name called directly. The
  `1, 0` is the version gate (see [bridge.md](/bridge.md)); EGL and CGL pass
  `0, 0` for "not version gated".
- The function-pointer typedefs are the **header's own** `PFNGL…PROC` lines,
  copied verbatim into the generated `src/gl-types.h` along with the base GL
  typedefs. EGL and CGL have no core PFN typedefs, so `gen-gl-src.php`
  synthesises one per prototype into `src/egl-types.h` / `src/cgl-types.h`
  from the same parse that writes the bindings.
- Marshalling only via `src/phpgl-support.{h,c}`; all glue only in
  `OpenGL\Bridge\Bridge` ([bridge.md](/bridge.md)). No other `phpgl_*`
  machinery may exist.
